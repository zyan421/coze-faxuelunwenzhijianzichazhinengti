# 实战案例库（v2.7 新增）

## 目的

把 v2 系列每一轮真实测试中暴露的 Agent 判断失误**案例化**，作为反面教材。比抽象规则更直观、更可学习。

每个案例的结构：
- **案例**：失误的具体表现
- **错在哪里**：失误的本质
- **该怎么做**：正确做法
- **指向的规则**：本案例对应应当遵循的 skill 规则

## 案例 1：脚注重复被定为致命级（v2.6 → v2.7 修正）

### 案例

审查某硕士论文，引言第 1 页脚注 1 与脚注 2 内容完全相同：

> 1 参见陈卫东：《司法责任制改革研究》，载《法学杂志》2017 年第 8 期，第 35 页。
> 2 参见陈卫东：《司法责任制改革研究》，载《法学杂志》2017 年第 8 期，第 35 页。

v2.6 Agent 写出的批注：

> 【引注格式】【**致命**】[原文核对]引言第 1 页脚注 1 与脚注 2 内容完全相同——连续两条脚注指向同一文献同一页是**明显的引注规范问题**，且**说明该处两段论点的来源未经仔细区分**

### 错在哪里

- **指控过严**：同段两脚注引同一文献同一页**本身不违反任何引注规范**，只是可以更简洁（合并为"同前注"）
- **措辞带指控色彩**："明显的规范问题"、"未经仔细区分"——给作者贴负面标签
- **未做反向举证**：该现象有合理解释（该段两个论点都源自该文献该页，正常学术写作）

### 该怎么做

降为 `minor`，措辞中性：

> 【引注格式】【**轻微**】[原文核对]引言第 1 页脚注 1 与脚注 2 指向相同文献页码。本身不构成规范违反，但建议检查两处论点是否真的援引自该页**不同内容**，若实为同一论点的重复引注，可合并为一条或改第二条为"同前注X，第35页"

### 指向的规则

- `rules/issues-schema.md` § 2.0a **严重度判定标尺** —— fatal 必须满足"反向举证测试"
- 反向举证：能找到合理解释（"两个论点都源自该页"）→ 不应定 fatal

## 案例 2：独创性问题挂在文献综述（v2.6 → v2.7 修正）

### 案例

审查论文题名"法官审判责任追究标准的困境**与对策**"，文献综述已引用叶汉杰《审判责任追究标准的困境**与出路**》——题名近似，叶文核心框架与本文第四章高度重叠。

v2.6 Agent 把批注挂在：第 10 页引言文献综述"叶汉杰指出..."这一句旁边。

### 错在哪里

- **挂载位置错位**：批注内容是"本文 vs 叶文 有什么独创性贡献"——这是**学术价值评价**问题
- 学术价值评价的读者是答辩委员，答辩委员翻论文找作者贡献时，看的是**作者宣称贡献的段落**，不是文献综述
- 批注挂在叶汉杰名字旁，作者只会觉得"是的我知道有这个学者"，意识不到要回答"你和他有什么区别"

### 该怎么做

挂在论文最接近"贡献说明"的位置——第 9 页引言"主要问题与结构"段"本文主张建立统一的审判责任追究..."：

> 【论证深度】【重要】[实质性硬伤]本文引言文献综述已引用叶汉杰《审判责任追究标准的困境与出路》（2019），本文题名与叶文高度近似。**本节作为全文最接近"贡献说明"的段落**，应明确阐述本文相对于叶文在哪些方面有实质性推进，否则独创性存疑

### 指向的规则

- `rules/annotation-placement.md` **原则三**：比较性问题挂在"贡献说明"的位置

## 案例 3：全文级问题挂在不相关的具体段落（v2.6 → v2.7 修正）

### 案例

审查中发现：2018 年《监察法》施行后，国家监察委对法官的监察权与法院内部审判责任追究制度的关系，全文未涉及——这是 2017 年后该领域无法回避的重大制度新变量。

v2.6 Agent 把这条全文级批注挂在：第 35 页赵作海案的段落旁（因为这段提到"侦查人员被追究刑事责任"）。由于段落与批注内容无逻辑关联，PyMuPDF 找不到合理 anchor，最终降级为**左上角便签**——用户根本不会注意到。

### 错在哪里

- **全文级问题没有单一锚文本**：监察法缺位不是某一句话的问题，是整篇论文的问题
- Agent 仓促选了一个"提到刑事追责"的段落作 anchor，但**赵作海案段不是讨论监察法的位置**
- 找不到合理 anchor → 降级为左上角便签 → **用户错过**

### 该怎么做

挂在"论文本应讨论这件事但缺失"的章节首段——第 36 页第三章"困境表现"章首段。这章本来就该扫描制度新变量，缺失监察法正是这章的硬伤：

> 【论证深度】【致命】[实质性硬伤]2018 年《监察法》施行后，监察委对法官的监察权与人民法院内部审判责任追究制度的关系，是该领域无法回避的重大制度新变量——两套追责路径是并行、竞合还是互补？全文几乎未涉及。**本章作为困境表现章应当扫描这一制度新变量**

### 指向的规则

- `rules/annotation-placement.md` **原则二**：全文级问题挂在论文相关章节的章首段

## 案例 4：PDF anchor 因空格陷阱失败（v2.6 → v2.7 修正）

### 案例

v2.6 Agent 写 issues.json，把"该法第 188 条首次"作为 anchor_text。逻辑文本看上去合理。

但 PDF 中实际字符是"该法第 188 条 首次"——PyMuPDF `search_for` 严格匹配，**搜不到**。结果降级为左上角便签。

### 错在哪里

- Agent 写 anchor 时基于"我看到的逻辑文本"，**不是 PDF 中的实际字符序列**
- PDF 排版（特别是 LaTeX/Word 导出的）会在**中文 ↔ 数字、中文 ↔ 字母**边界插入空格
- v2.6 工具没有空格容错搜索能力

### 该怎么做

**两层修复**（v2.7 同步落地）：

工具层（已实现 `tools/annotate-pdf.py`）：

```python
def _generate_space_tolerant_variants(text):
    """生成 anchor_text 的空格容错变体"""
    variants = [text]
    # 中文 + 数字/字母边界插空格
    v1 = re.sub(r'([\u4e00-\u9fa5])([0-9A-Za-z])', r'\1 \2', text)
    v2 = re.sub(r'([0-9A-Za-z])([\u4e00-\u9fa5])', r'\1 \2', text)
    # 两个方向都插
    v3 = re.sub(r'([0-9A-Za-z])([\u4e00-\u9fa5])', r'\1 \2',
                re.sub(r'([\u4e00-\u9fa5])([0-9A-Za-z])', r'\1 \2', text))
    return [text, v1, v2, v3]
```

规则层（`rules/anchor-text-locator.md` § 7）：

- PDF 输入下，**优先选连续中文（无数字/字母混入）的短句**作 anchor
- 失败的"该法第 188 条首次" → 改用"徇私枉法、滥用裁判权"（同句中纯中文短语）
- 失败的"有该法第 30 条明确列举" → 改用"以专章形式确立了法官惩戒制度"

### 指向的规则

- `rules/anchor-text-locator.md` § 7 **PDF 输入的特殊建议**
- `tools/annotate-pdf.py` v2.7 自动容错（兜底）

## 案例 5：表格内容错配被症状误判 + 编造证据（v2.5 → v2.6 修正）

### 案例

审查某本科论文表 3，表标题写"(2024)豫民终86号 vs (2025)藏民终17号"，但表内"案号"列实际是"(2024)豫民终86号 vs (2023)鲁民终356号"。

v2.5 Agent 看到表标题的"藏民终17号"，又因为论文别处出现过"桂民终17号"，**脑补**"省份代字笔误（藏 → 桂）"，并编造证据"脚注 46/47 均为(2025)桂民终17号"——但那页根本没有脚注 46/47。

### 错在哪里

- **只看表标题，没读表内容** —— 真问题是表标题与表内容整段错配
- **凭印象推理 + 编造证据** —— "脚注 46/47"是 Agent 凭"我从别处看到过桂民终17号"瞎填的
- 这是**"自报家门式守门"的失败**：Agent 自称"原文核对"但没真做核对

### 该怎么做

正确诊断：

> 【实证】【致命】[原文核对]表 3 标题与表内容不一致：标题写"豫民终86号 vs 藏民终17号"，但表内案号列实际是"豫民终86号 vs **鲁民终356号**"。建议同步更新

### 指向的规则

- `rules/table-audit.md` 表格审查规则 —— 审查表格必须先读表格内容
- `rules/academic-integrity-guard.md` 假阳性守门 —— 提及脚注号必须先 verify 脚注实际内容

## 案例 6：第四章自动编号被误判为漏字（v2.5 → v2.6 修正）

### 案例

审查论文第四章，标题文本节点是"实践困境"（没有"四、"两字）。v2.5 Agent 报告"第四章正文标题遗漏了章号'四、'"。

实际情况：第四章使用了 Word 自动编号 `<w:numPr>` numId=1，"四、"是渲染时由 Word 编号系统注入的字符——文本节点里看不到。其他五章用手写"X、"前缀。

### 错在哪里

- Agent 只读 `<w:t>` 文本节点，完全没读 OOXML 样式属性层
- 看不到 "四、" 就直接判"漏字"，没考虑"是不是自动编号渲染的"

### 该怎么做

正确诊断：

> 【结构】【轻微】[OOXML分析]章节编号混用：第四章标题使用 Word 自动编号（`<w:numPr>` numId=1），其余五章手写"X、"。混用容易在转格式、章节移动等场景出错

### 指向的规则

- `rules/ooxml-style-check.md` OOXML 样式层核查指引 —— 看不到"X、"时必须先查 `<w:numPr>`

## 案例 7："幽灵引用"措辞过激（v2.5 → v2.6 修正）

### 案例

v2.5 Agent 把"参考文献列出但正文未脚注引用的条目"称为"幽灵引用"，并定为 issue。

### 错在哪里

- **"幽灵引用"是计算机学科查重领域的术语**，在法学论文批注里看着像指控
- 更严重的是：**这本不是问题**。参考文献本质是"阅读/参考过的文献清单"，并不要求每条都在脚注中显式调用
- 作者完全可能真读过、参考过，但行文中未必用到引注

### 该怎么做

v2.6 起：

- **取消"幽灵引用"这个概念**，删除对应 issue 类别
- 只保留单向"脱钩"：脚注引用了但参考文献漏列（这才是真问题）
- 全文措辞中性化：用"未匹配""疑需核实"代替"幽灵""涉嫌""造假"

### 指向的规则

- `rules/issues-schema.md` § 9 **术语风格指南** —— 禁用高刺激词
- `rules/orchestration-flow.md` § 5 —— `in_refs_not_in_text` 不再生成 issue

## 反思：v2 系列演进的元教训

把 7 个案例放在一起看，能提取出 Agent 容易犯的 4 类系统性错误：

1. **凭印象推理代替核对原文**（案例 5、6）—— 看到部分文本就脑补全貌
2. **过度负面措辞**（案例 1、7）—— 把可解释的现象升为指控
3. **挂载位置错位**（案例 2、3）—— 挂在问题出现的位置，不是读者最该看到的位置
4. **环境/工具盲区**（案例 4、6）—— 不知道 PDF 有空格陷阱、不知道 docx 有 numPr 自动编号

每一类都已在 v2.7 用对应规则约束。未来若发现新失误，应当继续以"案例 + 规则"的形式补入本文件。
