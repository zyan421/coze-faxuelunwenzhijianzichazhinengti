## §0 时间基准（v2 新增）

**触发**：用户新消息到达，主工作流启动前

**做什么**：
1. 从宿主环境读取当前系统日期（UTC + 本地时区）
2. 在整个审查上下文中保存 `current_date = YYYY-MM-DD`
3. 所有后续涉及"未来 / 过去"判断的环节均参考该基准

**为什么重要**：论文里常出现 2024/2025/2026 年等日期，必须对照**当前日期**判断，不能硬编码"X 年之后就是未来"

**伪代码**：

```python
from datetime import date
current_date = date.today()
# 传入所有子模块
context["current_date"] = current_date.isoformat()
```

**强制约束**：Agent **禁止**在未获取 current_date 的情况下，对论文中任何日期做出"未来 / 虚构"的判断。如果 Agent 想说"这是未来日期"，必须在报告中引用 current_date 作为比较基准。

## §4 调用 legal-thesis-reviewer（九大维度审查）

**v2 新增约束（假阳性守门，U5）**：

1. **致命指控必须证据闭环**：任何 `severity=fatal` 的 issue，必须在 `problem` 字段同时包含两类内容：
   - 具体证据（原文摘录或页码）
   - 为什么构成致命（对应规则引用）
2. **结构性指控必须多处证据**：
   - "章节重复" → 必须在报告里给出 ≥ 2 段具体对比文字
   - "参考文献脱钩" → 必须给出完整对比表（见 §5.1 citation-crossref）
   - "脚注编号重复" → 必须给出重复号在原 pdf 的页码（而非提取文本行号）
3. **"疑似"是默认语气**：除非证据链闭环至可被反驳到不留漏洞，否则用"疑似/或许/建议进一步核实"，不用"确实/明显/显然"
4. **区分文本分析与联网核实**：
   - 基于文本分析的怀疑（结构重复、语言冗余） → 报告中标注 `[文本分析]`
   - 基于联网核实的确信（引用不存在、条文号错误） → 报告中标注 `[联网核实]` + 来源 URL

**v2.7 新增约束（严重度判定标尺与挂载位置原则）**：

5. **严重度判定按标尺**：参 `rules/issues-schema.md` § 2.0a 的判定标尺。每条 fatal 必须通过"反向举证测试"——能否找到合理解释推翻这个指控？若能，不应定为 fatal
6. **批注挂载位置按原则**：参 `rules/annotation-placement.md`。每条 issue 写 anchor_text 前先回答：(a) 这是不是全文级或跨章节问题？(b) 这是不是比较性/贡献评价问题？(c) 读者最该在哪里看到这条批注？
7. **建议阅读案例库**：参 `rules/case-studies.md`。这是 v2 系列每一轮真实失误的反面教材，比抽象规则更直观

## §4.5 实质性维度专章审查（v2.6 新增）

**v2.5 实战暴露的核心问题**：v2 偏向形式问题（笔误/章号/引注格式），对实质性维度（问题意识、论证深度、逻辑周延、自相矛盾、研究承诺与产出兑现）关注不足。

**v2.6 强制规则**：

1. Agent 在 §4 九大维度审查的基础上，**必须**按 `rules/substantive-review.md` 的七维度清单逐项审视论文
2. 至少产出 5-10 条实质性 issue（severity ∈ {fatal, major}），覆盖类别 ∈ {argumentation, empirical, literature-review, legal-norms, academic-integrity}
3. **实质性问题占比阈值**：
   - 本科论文 ≥ 50%
   - 硕士论文 ≥ 60%
   - 博士论文 ≥ 65%
4. 不达标 → 触发"再审一轮"

详见 `rules/substantive-review.md`。

### §4.5.1 OOXML 样式层核查（docx 路径）

**v2.5 实战暴露**：抽取链路只读 `<w:t>` 文本节点，忽略 OOXML 样式属性层（pStyle、numPr、rPr）。

**v2.6 强制规则**：docx 路径下，Agent 在 §4 评分前必须用 `rules/ooxml-style-check.md` 中的方法检查：

- 章节标题样式一致性（pStyle 是否统一）
- 章节编号机制一致性（手写"X、"vs `<w:numPr>` 自动编号）
- 列表样式、字体异常切换

**特别提醒**：当文本节点看不到某段开头的"X、"时，**必须先检查 `<w:numPr>`**，不能直接判定"漏字"。Bug 案例详见 `rules/ooxml-style-check.md` §1。

### §4.5.2 表格审查规则

**v2.5 实战暴露**：藏民终17号事件——Agent 看到表标题里某个案号，凭印象脑补"省份代字笔误"，并编造了不存在的脚注号作为证据。

**v2.6 强制规则**：

1. **审查表格时必须先读表格内容再评价表标题**（详见 `rules/table-audit.md` §2）
2. **提及脚注号/页码/表号时必须先 verify 实际内容**——不能凭印象写"脚注 X 引用了 Y"
3. **`[原文核对]` 表格类 issue 必须有具体表内容引述作为证据**

---

**v2 新增步骤**：

### §5.1 自动生成引用交叉对比表（U8）

在 CC 本身的引注格式校对之外，强制执行：

```bash
python3 tools/citation-crossref.py <原.pdf> <交叉表.json>
```

输出**三份对比清单**：

- `a_in_text_not_in_refs`：正文/脚注出现但参考文献表未列出的作者（**脱钩** —— 规范问题，应在报告/批注中列出）
- `a_in_refs_not_in_text`：参考文献列表有但正文未脚注引用的条目（**v2.6 起不再视为问题**，因为参考文献本质是"阅读/参考过的文献清单"，并不要求每条都在脚注中显式调用；该清单仅作为信息提示，不进入 issues.json）
- `a_matched`：两侧都有，对照成功

**严格基于 `a_in_text_not_in_refs` 这一份清单生成"脱钩"类问题**，不再由 Agent 主观判断。`a_in_refs_not_in_text` 仅供信息参考，**不得**生成对应 issue。

## §6 联网核实（v2 改为强制执行）

**v1 降级过度的问题**：v1 允许"联网工具返回噪声大 → 整章降级为待用户核实"。v2 改为：

1. **识别高优先级可核实事项**（规则详见 `rules/online-verification-unified.md` §2.1）：
   - 法律 / 司法解释 / 规范性文件的**存在性与条文号**
   - 案号 / 裁判文书
   - 期刊论文的**作者 + 期号 + 年份**组合
   - 统计数据的出处
   - 机构 / 人物身份
2. **每条高优先级事项至少尝试 2 次搜索**，用不同关键词组合
3. **失败才降级**：具体失败的条目才标注"待用户核实"；其他成功的条目正常呈现
4. **成功的核实结果必须附来源 URL**，不附来源的不算"已核实"

**当前日期关联**：联网核实任何"截止时间 / 最新版本"类问题时，必须对照 `current_date`（§0）。

## §7 合并输出 + 节点 E（v2 新增匿名化选项）

**节点 E（U9 新增）**：合并前询问用户：
- "是否对报告进行匿名化（作者 / 单位 / 指导教师占位）？"
- 默认 **不匿名**（作者本人审查自己论文的场景无需匿名）
- 用户选"是" → 报告中用占位符 `{{author}} / {{institution}} / {{supervisor}}` 代替

**合并输出产物**（与 v1 一致，但 pdf 场景的产物变化）：

- `{论文名}_unified-report.md`
- `issues.json`（v2 schema 含 anchor_text）
- `{原名}.positions.json`（pdf 输入时，由 §2 extract-pdf-text.py 产出）
- `{原名}.crossref.json`（§5.1 产物）

## §8 批注生成询问（节点 D，v2 改用 annotate-pdf）

- 输入 docx → 调 `tools/inject-docx-comments.py`（v1 路径保留）
- 输入 pdf → 调 `tools/annotate-pdf.py`（**v2 新主路径**），产出 `{原名}.annotated.pdf`
  - 任何 pdf 阅读器（WPS / Chrome / Preview / Adobe / Foxit）可直接打开查看批注
  - 无需手工导入，零配置
- 用户明确要 XFDF 时，才调用 `tools/generate-xfdf.py`（v1 路径降级为备用）
