# 实质性维度强制审查清单（v2.6 新增）

## 1. 背景与定位

**v2 实战暴露的核心问题**：v2.0-v2.5 在多次实测中（详见 CHANGELOG v2.4/v2.5/v2.6），生成的批注严重偏向**形式问题**——笔误、章号、引注格式、人名不一致等——而对**论文的实质性维度**关注严重不足：

- v2.5 测试刘梓璇论文：形式问题占比 60%，实质性问题仅 15%
- 用户反馈："检查功能或者批注，对论文选题的问题意识、逻辑的周延性、核心观点论证的深度、遗漏的不应忽略的问题、自相矛盾之处等实质性的方面，关注得不够"

这一反馈触发本规则文件的引入。**v2.6 的核心定位转变**：从"机械底线核查器"升级为"形式 + 实质双轨审查器"。

## 2. 强制审查清单（七维度）

Agent 在生成 issues.json 前，**必须**按以下清单逐项检视论文，每个维度至少形成一条记录（即便是"未发现问题"也要登记）：

### 维度 1：选题与问题意识

- 论文是否提出**可证伪/可检验**的假设？还是仅"指出现象"？
- 选题在该领域是否已有大量重复研究？本文的边际贡献在哪？
- 问题意识是否清晰——一句话能说清"本文研究什么、贡献什么"吗？

### 维度 2：论证深度

- 核心论点是否**回应至少一个明显反驳**？
- 是否做过**反例测试**——"我的论断在 X 反例下是否成立"？
- 政策建议/规范建议是否回应"反对声音"？

### 维度 3：逻辑周延

- **摘要 → 第 N 章 → 结论** 的核心命题是否前后一致？
- 有无**自相矛盾**（例如摘要主张"范式转变"但结论又退回"原范式"）？
- 论证链条是否完整（前提 → 推论 → 结论），还是中间有跳步？

### 维度 4：研究承诺与产出兑现

- **摘要/引言/研究价值章承诺**的"将考察 X / 区分 Y / 对比 Z"是否在后文兑现？
- 研究方法宣称"问卷调查""实地调研""案例分析"——后文是否真有相应产物？
- 样本/案例规模是否与研究方法的承诺相匹配（"类型化研究"vs"代表性研究"的差别）？

### 维度 5：遗漏检查

- 同主题的**标志性前序研究**是否被对话？（例如证券虚假陈述实证研究，鲍彩慧 2017 年 806 份判决书的研究是绕不开的前序）
- 数据中明显的**反例**是否回应？（例如样本中 20% 案件与核心论断不符，论文是否承认？）
- **比较法部分**是否对该领域真正核心的几个国家/案件做了对话？还是只罗列了不相干的零散学者？

### 维度 6：理论 - 实证闭环

- **理论章建立的分类/框架**是否在实证章被使用？
- **实证发现**是否反哺理论？还是实证章只是"陈列数据"，理论章只是"罗列概念"，两章各说各话？
- 论文使用的理论方法（如动态系统论、利益衡量论、法律经济学）是否**论证了选择该方法的理由**？

### 维度 7：建议可行性

- 政策建议是否回答"**谁来实施 / 时间表 / 障碍 / 反方意见**"四要素？
- 建议是空泛口号（如"加强监管""完善制度""推动一体化"），还是有具体抓手？
- 立法论建议是否回应"修法的政治成本/制度路径"？

## 3. 强制性约束

**v2.6 起，Agent 在 §4.5（详见 `orchestration-flow.md`）的实质性维度审查中，至少需产出 5-10 条实质性 issue（severity ∈ {fatal, major}）**，且必须满足：

- **实质性问题占比 ≥ 50%**（本科论文）/ **≥ 60%**（硕士论文）/ **≥ 65%**（博士论文）
- 若占比不达标，触发"再审一轮"——重新按本清单逐项检视

实质性问题包括以下类别：

- `argumentation`（论证缺陷、自相矛盾、反驳缺位）
- `empirical`（实证方法论缺陷、数据可重现性问题、样本偏差）
- `literature-review`（综述不完整、未对话前序研究）
- `legal-norms`（法律规范理解错误、比较法误读）
- `academic-integrity`（伪造引用、张冠李戴）

形式问题（仅作辅助）：

- `language`（语言笔误、表述病句）
- `citation-format`（引注格式问题）
- `structure`（章节结构问题、目录问题）

## 4. 一份"好的实质性 issue"应当具备

每条实质性 issue 的 `problem` 字段必须包含：

1. **[标签]**：`[实质性硬伤]`、`[联网核实]`、`[原文核对]`、`[OOXML分析]` 等明确证据来源
2. **症状描述**：论文 X 处出现的具体表述
3. **冲突点**：与什么（论文别处 / 已知事实 / 学界共识）相矛盾
4. **后果评估**：这个问题为什么是 fatal/major（不能只是"建议改"）

每条实质性 issue 的 `suggestion` 字段必须包含：

1. **具体的修改方向**（不是空泛"建议优化"）
2. **可参考的真实文献/案例/数据来源**（便于学生按图索骥）
3. **如果作者坚持原立场，应当补充什么论证**（让作者有选择权而非强制改）

## 5. 反例：什么不算实质性 issue

- ❌ "本章论证不够深入" —— 太空泛
- ❌ "建议补充更多数据" —— 没说补什么数据、为什么需要
- ❌ "国外研究可以更丰富" —— 没指出关键遗漏
- ✅ "摘要承诺将考察诱多型与诱空型,但 86 份样本中诱空型分布、判决特征均未呈现 → 研究承诺与产出失约"

## 6. 与形式问题的关系

形式问题（笔误等）**可以批量列出**，每条很短即可；实质性问题**必须详细论证**，每条 problem 200 字内（schema 上限），但 suggestion 可以展开。

报告呈现时：

- §④ 实质性维度审查（v2.6 新增）—— 详细呈现 5-10 条实质性硬伤
- §⑤ 各维度详细评分（按 9 大维度细化）—— 引用上面的 issue
- §⑧ 语言笔误清单（汇总）—— 形式问题集中列表

| 论文 | v2.5 实质性占比 | v2.6 实质性占比 |
|---|---|---|
| 刘梓璇《证券虚假陈述》 | 15% (3/20) | **64% (14/22)** |
| 胡文仲《生成式 AI 著作权》 | — | **44% (12/27)** |
| 谢佳谕《政府采购电子化平台》 | — | **63% (12/19)** |
